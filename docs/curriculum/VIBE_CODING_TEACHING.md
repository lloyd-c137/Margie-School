# Margie School · Vibe Coding 教学交互方案

> 2026-11-28 · Draft v0.1
> 状态：纯线上、手机端完整体验为已确认约束；Brilliant 式教学交互为明确偏好；Playable Curriculum、交互原语、课程组织与 MVP 范围为待验证设计。本文不代表已完成产品或教学实验。

## 1. 目的与硬性约束

Margie School 是完全免费、非营利的 AI-native 教育实验。Vibe Coding 是首个学习领域，而不是一套特定 AI 工具的培训。教学需帮助学习者形成可迁移的理解、判断、问题分解、验证和创造能力；AI 生成作品本身不是掌握证据。

- **Online only**：课程、实验、必要讨论、实践与反馈均在线完成，不依赖线下活动。
- **Mobile First / Full Participation**：手机学习者可以完成全部核心学习任务，而不只是观看、签到或提交答案。不得要求另用电脑或物理键盘。
- **Brilliant-inspired**：优先让知识成为可操作的对象，而非将传统教材、长视频、PPT 或桌面 IDE 缩小到手机。
- 保持学习者自主选择目标、探索路径和表达方式；不以统一产出或打卡维持学习。
- 第一课《我们一直在等你》是教育哲学启蒙，不能强行安排 Build 或把立场认同作为成绩。

异步自学是否为唯一形式、是否提供真人在线引导、设备与浏览器覆盖范围、最终技术选型均未确认。完整手机参与是硬要求，具体交互设计仍需测试。

## 3. 教学形式候选：Playable Curriculum（可玩的课程）

这里的「可玩」不是用金币、排行榜、连续打卡包装传统题库，而是让学习者能操作知识、提出假设、观察反馈、修改规则并创造自己的东西。

建议将课程组织为可组合的交互体验，而不是强制的统一关卡。学习循环：

**Encounter 遇见问题 → Explore 探索 → Understand 理解 → Experiment 验证 → Create 创造 → Reflect 反思与迁移**

这是非线性的循环。学习者可跳转、回看、反复实验，也可在真实项目遇到问题时进入对应知识体验。首次课不要求进入 Create 环节或编程；必要时先进行事实讲解、示范或基础知识学习。

推荐微观教学机制：**先体验，后命名，再应用。** 在探索类任务中，先观察现象、提出规则，再引入概念与正式术语；不把此顺序变成绝对教条，避免无指导的盲目探索。

## 4. Learning Primitives · 教学交互原语

| 原语 | 学习者操作 | 反馈 / 证据 | 示例 |
| --- | --- | --- | --- |
| Observe / 观察 | 查看运行过程、比较现象 | 状态变化与差异 | 同一页面刷新前后 |
| Predict / 预测 | 在运行前描述预期 | 预测与实际对照 | 点击按钮后数据如何改变 |
| Manipulate / 操作 | 拖动、点击、调整输入 | 即时可见因果关系 | 改变程序状态 |
| Simulate / 模拟 | 改变环境、触发异常 | 模型响应及假设 | 服务器离线、错误请求 |
| Disassemble / 拆解 | 展开组件、检查数据流 | 组件职责与连接 | 浏览器、服务器、数据库 |
| Sequence / 排列 | 重排步骤、定义过程 | 流程结果、错误位置 | 算法、任务分解 |
| Experiment / 实验 | 修改条件、反复验证 | 测试结果与反例 | API 参数与响应 |
| Decide / 决策 | 选择或提出不同方案、解释理由 | 取舍、证据和不确定性 | 数据保存在何处 |
| Discover / 发现 | 遇到新限制后修正规则 | 新约束下的结果 | 功能需求逐步演化 |
| Create / 创造 | 自然语言或触屏构建、修改作品 | 可运行作品及贡献记录 | 自选 Web 应用 |
| Explain / 解释 | 用文字、语音或操作表达原理 | 理由、例子、可验证预测 | 解释为什么刷新后数据丢失 |
| Transfer / 迁移 | 在不同情境重新应用 | 独立表现及需要的帮助 | 对新应用识别相同结构 |

原语是课程设计词汇，不意味着必须先实现 12 个组件。对开放思想讨论，反馈应展现合理反例与取舍，而不是按是否认同 MS 判分；对可验证的技术任务，反馈应明确运行结果与错误原因。

## 5. 六种交互教学形式

1. **Interactive Explainer**：可操作知识模型，短叙事、预测、运行、解释及变式实验。
2. **Interactive Story**：学生进入情境，通过选择、理由、反事实和后果探索复杂议题。
3. **AI Simulation**：在受控环境中使用自然语言指导代理，观察歧义、限制、执行与反馈；模拟与真实运行必须标注。
4. **Agent Replay**：保存真实开发步骤、提示、代码变化和故障；学习者能暂停、预测、从某一步分叉并比较结果。初版可使用明确标注的预制分支，不必先实现任意回放分叉。
5. **AI Dialogue**：在当前实验或知识对象的上下文中提供解释、提示、反例与掌握验证。不能只是无上下文聊天框；避免直接代替学习者完成应由其思考的部分。
6. **Creative Playground**：后续通过手机自然语言或触屏进行真实软件创造、预览、测试、调试与回退。Coding Agent 执行任务，Tutor 支持理解；具体集成方式未确定。

## 6. 示例 A：Talk to a Server（技术交互体验）

目标：学习者能够根据实验区分客户端、服务器、请求、响应、参数和连接故障，并将其应用到一个不同场景。

1. 呈现一个手机需要获取信息的任务，不先罗列术语。
2. 让学习者选择天气或音乐数据，修改城市参数，预测返回内容。
3. 点击发送请求，观察从客户端到服务器的可视化路径与结构化响应。
4. 切换不存在的接口，观察 404；关闭服务器，观察连接失败。避免把 404 和网络连接失败混为一谈。
5. 让学习者解释差异，提出一个能够区分两类错误的测试。
6. 在新的任务（如获取图书列表）中验证其能否构造合理请求并解释结果。

初版采用固定本地数据与确定性模拟，界面显式标注「模拟」；不得显示虚构数据为真实天气。后续可加入受限真实 API 实验，但凭证不得暴露在客户端，需考虑费用、速率、安全与隐私。

可选交互原型：两个纵向排列的客户端/服务器卡片，触屏选择请求参数、发送、开关服务器、观察响应。无需横向滚动或输入代码。

## 7. 示例 B：FOUNDATION 001 · 我们一直在等你

首课标题和教育哲学内容不变，交付形式改为必须纯线上且手机完整参与。以下是新的互动编排候选：

- **Arrival**：短叙事开场，允许私人回答「如果没人规定你应该学什么，你想探索什么？」。
- **Invisible Rules**：选择、解释、比较不同教育制度的案例；提供相反论据和事实背景。
- **What Is Learning?**：通过小型交互问题体验「看见答案」与「能迁移运用」的区别。
- **Curiosity / Creativity / Judgment**：提出问题、构想多种方案、审查各自的限制与证据。
- **Redesign Education**：使用手机可完成的方案编辑器或简单文本提出制度设计，观察模型假设下的结果。不能把简化模拟的输出当作真实社会因果证据。
- **Question Margie**：主动提出对 MS 的批评，反馈不以观点一致性评价；异步阅读不同观点为候选，可选在线真人讨论。
- **Your First Question**：私人反思与自选探索方向，允许不分享。

此前 90 分钟、6–10 人和现场式工作坊只是历史候选，不能成为新的手机交付前提。异步单人是否为默认模式、是否分为多个短体验及最终时长，均待试讲验证。

## 8. Mobile First 验收要求（建议操作化）

- 使用一部普通手机即可从进入课程、阅读、交互、提交、获得反馈，到核心学习任务结束；无必需电脑、外接键盘或线下环节。
- 主要路径竖屏可用；避免桌面多栏 IDE、横向表格及精细拖拽成为阻塞，必要时提供点击替代。
- 操作目标适合触屏，文本可读、缩放可用；颜色不是唯一反馈；语音/动画均有可替代方式。
- 能在中断后恢复进度；弱网络或请求失败有可理解的状态和重试路径，不能悄悄丢失作品。
- 不强制长文本输入、摄像头或麦克风；自然语言和语音可选，具备文字与触屏替代路径。
- 不依赖外部付费账号或设备实现核心教学；验证地区、浏览器、语言、可访问性及实际算力成本。
- 若后续课程需要真实构建，手机端必须能查看运行结果、修改、测试、回退并完成对应掌握任务。

建议至少用 iOS Safari 与 Android Chrome 的真实设备验收，而非只查看桌面响应式截图。目标设备/最低版本、网络限制、具体通过阈值待定。

## 9. 评估与第一轮验证方案（建议）

不首先建设完整 LMS、生成式课程引擎或 IDE。建议先选择两个代表性体验：首课中的一个开放思想实验，以及一个技术交互实验（Talk to a Server 或状态实验）。使用移动端原型验证学习方式，而不是追求功能数量。

| 维度 | 最小观察证据 |
| --- | --- |
| 交互可用性 | 手机独立完成任务、操作阻塞、中断恢复与可访问性观察 |
| 理解 | 先预测、再操作，能解释实际结果 |
| 迁移 | 改变场景或参数后，独立应用同一概念 |
| 判断力 | 能给出理由、检验反例、承认不确定性；不以反传统立场计分 |
| 自主性 | 能选择问题、调整探索方向、不依赖主持人代做 |
| 成本 | 单个交互的制作、维护、运行及必要 AI 成本 |

建议招募小规模零基础学习者进行手机端走查。明确同意与隐私，未成年人适龄保护；数据最小化、允许不公开个人反思。原有约 10 人构想不是已完成招募。短期可用性试验不能证明长期能力提升，后续需合理基线、独立任务和延期评估。

## 10. 未决事项

- 是否采用 Playable Curriculum 作为正式教学模式名称与组织方式。
- 课程知识地图、必要基础知识、代码阅读深度、AI 与人各自承担的认知工作。
- 首课线上编排、异步/同步组合、真人引导及同伴互动机制。
- 首批交互原语与技术实验选题；是否使用真实 API、运行环境或先做模拟。
- 自适应程度、AI Tutor 反馈策略、掌握验证与自由探索的平衡。
- 首版使用网页、原生应用或其他平台；课程内容模型、交互组件及后续 Coding Agent 集成方式。
- 免费服务的可持续性、AI 成本、安全、隐私与移动端完整验收。
